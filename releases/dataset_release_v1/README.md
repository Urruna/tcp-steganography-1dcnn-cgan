# Dataset Release: TCP Proxy Traffic (Normal / Stego)

This package contains three traffic data sources:

1. Historical Docker Normal Dataset
2. Current Protocol-Stego Normal Dataset
3. Current Protocol-Stego Dataset

They are deliberately kept in separate directories and must **not** be mixed
without an explicit experiment design.

## Source mapping

```text
Historical Normal
        ↓
early Docker communication baseline

Protocol Normal
        ↓
current experimental control group

Protocol Stego
        ↓
current experimental group
        ↓
800/1200 application-layer length modulation
```

## Machine-learning-ready data

```text
X = [N, 4, 128]
y = [N]
```

- `N` = number of windows
- `4` = features
- `128` = sequential events per window

Feature order:

```text
0 = direction
1 = length
2 = inter_arrival_time
3 = cumulative_bytes
```

Label:

```text
0 = Normal
1 = Stego
```

The Stego label in this release specifically means:

> traffic carrying the current 800/1200 application-layer length modulation.

It does **not** mean "all possible steganographic traffic".

## Minimal loading example

```python
import numpy as np

X = np.load("dataset_release/protocol_stego/processed/X.npy")
y = np.load("dataset_release/protocol_stego/processed/y.npy")

print(X.shape)   # [138, 4, 128]
print(y.shape)   # [138]
print(np.unique(y, return_counts=True))
```

Important notes for the CNN member:

1. Do not change the feature order.
2. Do not re-split windows randomly; use the provided session-level splits.
3. In the current data, `direction` is constant (+1) because only
   Client → Server traffic was recorded.
4. Normal events are mostly 1024 bytes, while Stego events are 800/1200 bytes.
   This means the current CNN task primarily tests detection of the
   800/1200 modulation signature, not general steganography detection.
